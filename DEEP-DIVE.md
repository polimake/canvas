# canvas2 deep-dive — synthesized audit (6 dimensions, adversarially verified)

All entries below survived verification. Corrections from the adversarial pass are folded in. File paths and Excalidraw API names are verified against the installed `@excalidraw/excalidraw` 0.18.1.

---

## Top 5 moves (impact per effort)

1. **Self-host Excalidraw fonts** (S) — fonts load from `esm.sh` at runtime today and the enforcing CSP on polimake.com/studio blocks that origin; the production multi-zone deployment renders wrong fonts *now*.
2. **`mutate.ts` version-bump discipline** (M) — verified: 0.18.1's undo store diffs by `id+versionNonce` only, and canvas2's spread-patches never bump it, so **resize/move/rename/lock/align are silently non-undoable today**; this also unblocks 3 other fixes and any future scene merging (autosave, MCP edits).
3. **Viewport-following active page** (S) — pan to page 3 and export/Texto/Fondo/Tamaño still hit page 1; a daily wrong-page-export footgun, fixable with the imperative `api.onScrollChange` + `getVisibleSceneBounds` (zero adapter changes for the subscription).
4. **Envelope format + sanitizer bypass + format-routed mount** (M) — the gate on the entire persistence phase; without the `format:'excalidraw'` marker a saved scene corrupts `designs.pages` and gets fed to the frozen clone editor.
5. **onSceneChange emission hygiene** (S) — emitted scenes include deleted-element tombstones and never-pruned dataURL files, and re-emit on every pan/zoom; this is what drives the silent localStorage quota failure (total work loss, no signal) and would bloat every future D1 row.

## Product / UX

**Viewport-following active page + keyboard page nav** — `activePageId` only changes on chip click, so every active-page action (export at PageNavigator.tsx:162-216, Texto :434, Fondo :463, size/add-inheritance) silently targets the wrong artboard after a manual pan. Subscribe once in Canvas2.tsx via the imperative `api.onScrollChange` (returns an unsubscribe; no adapter change needed), debounce ~150ms, compute the visible rect with `getVisibleSceneBounds(appState)` (re-export via src/excal.ts), pick the frame with the largest visible area, `setActivePageId`. Note: `listPages`' `PageInfo` carries no x/y — intersect against the frame elements from `getSceneElements` or extend `PageInfo` with coordinates. Also follow selection (`selectedElementIds` in the existing onChange) and add PageUp/PageDown nav, skipped while `appState.editingTextElement` is set. **S–M, high.**

**Gate chrome on viewMode** — Canvas2.tsx:197-208 renders PageNavigator/LayersPanel unconditionally; neither knows `viewMode`, and their mutations go through `api.updateScene` un-gated, so a "read-only" reviewer can delete pages and persist it (blocker for PARITY roadmap item 5; PARITY's "read-only ✔ already wired" is overstated). Thread `viewMode` into both panels: keep chips + Exportar, hide the action cluster, +Página, Texto/Fondo/Tamaño; LayersPanel rows become click-to-select only. Clone precedent: PageSettings.tsx `!isCommentMode` gating. **S, high.**

**Page thumbnails + grid overview** — the strip is text chips ("Página 1"), reorder is blind single-step chevrons; for a 6-slide carousel the user can't see which page is which — the biggest regression vs the clone (SortablePageSettings live previews, drag-reorder, hover-`+`). (1) Small previews in chips via `captureThumbnail(api, { pageId, maxSize: 96 })` (export.ts:97-108), cached per page keyed on member `element.version` sums, refreshed via the existing `api.onChange` throttled ~1s. (2) New `PageGridOverlay.tsx`: full-canvas grid of larger thumbnails, click-to-jump, HTML5 drag-reorder (extend `movePage` to accept an absolute target index), per-tile duplicate/delete. **L, high.**

**Safe-area overlays for Story/Reel/feed** — the presets are social-first but nothing shows where platform chrome covers the design; text under the TikTok caption is discovered after publishing. New `safeArea.ts` + `SafeAreaOverlay.tsx`: map the active frame's rect to screen via `sceneCoordsToViewportCoords` (public; needs `offsetLeft/offsetTop` from `getAppState()` — add to src/excal.ts), recompute on `onScrollChange`+`onChange`, draw dashed regions in a pointer-events:none div (non-exported by construction). Ship zone definitions keyed by `PAGE_SIZE_PRESETS` key **as editable data** — the pixel values (top ~250 / bottom ~310 / right rail) are community heuristics, not published specs. Same infra later feeds the AI design lint. **M, high.**

**Kill window.prompt/confirm** — rename uses `window.prompt` in two places (PageNavigator.tsx:225, LayersPanel.tsx:355), custom size is a prompt whose regex silently swallows `1080*1350` / `1080 1920` (PageNavigator.tsx:181-185), and delete uses `window.confirm` (:231). Blocking, unthemed, inconsistent with studio (8 prior confirm→ConfirmDialog migrations). Fix dependency-free: inline chip rename (double-click → controlled `<input>`, Enter/Esc), a two-field width/height form with aspect-lock + visible validation inside the existing PopupMenu (clone pattern: HeaderFileMenu.tsx:527-636, 100–8000px bounds), and delete via a two-step button or an injectable `confirmAction` prop for the host's brand ConfirmDialog. **S, medium.**

**Insert pages after the active page** — `addPage`/`duplicatePage` always append at `nextPageX` (pages.ts:76-80, 131-161, 361-421); duplicating slide 2 of 10 lands at position 10 and `movePage` is single-step. Add optional `afterPageId` (default: active): create at `source.x + width`, shift right-side frames+members by the new width (the existing map-with-dx pattern), `relayoutPages`. Handle the naming collision (`Página ${count+1}` mid-sequence → renumber or derive from position); update the duplicate/relayout tests. **S, medium.**

**Text presets: placement, scale, color** — every preset anchors at the same point (text.ts:53-54) so Título+Subtítulo overlap exactly; sizes are absolute 64/40/24 regardless of page width; and — verified worse than reported — the skeleton omits `strokeColor`, so `convertToExcalidrawElements` applies the library default `#1e1e1e`, making preset text **literally invisible** on the `#1e1e1e` BG swatch. Fix in `insertTextPreset`: per-preset anchors + cascade offset, `fontSize × pageWidth/1080`, strokeColor by luminance of `getPageBackground(api, pageId)`. Pure, mock-testable. **S, medium.**

**Brand + in-document color swatches** — `BG_SWATCHES` is 7 hardcoded pastels (PageNavigator.tsx:141); no brand palette, no "colors used in this design". Add `brandColors?: string[]` to Canvas2EditorProps; add an "En este diseño" row scanning `getSceneElements()` on menu-open — exclude paper chrome via the `isPageBackground(el)` customData marker (background.ts:22-24), **not** by hex (a legitimately-white page background would be filtered). **S, medium.**

**First-run format chooser + social default** — fresh docs open on the legacy 1640×924 "Lienzo clásico" with zero guidance. Correction on wiring: on first run CanvasWorkspace passes `initialScene=null` and Canvas2.tsx bakes `createBlankScene` into `initialData` (:109-126), so the "settled" branch never fires — gate the chooser on `initialScene == null && !pageSize` in Canvas2Editor, show it over the auto-created page, and `resizePage(page1)` on choice. Change `DEFAULT_PAGE_SIZE` → 1080×1350 (ripples into `createBlankScene`, unit tests, and the PARITY Playwright boot expectation). **M, medium.**

**Strip scalability past ~6 pages** — no N/M counter, no auto-scroll on activation, and the active chip balloons with up to six inline icon buttons (PageNavigator.tsx:288-305, 344-361). Fix: `scrollIntoView({inline:'nearest'})` on activation; collapse the six actions into one "⋯" PopupMenu — **rendered at strip root/fixed-position, not inline in the chip** (the file deliberately keeps popups outside the scroll container to avoid clipping, :379-380); add an N/M counter and fade-edge gradient. **S–M, medium.**

## Persistence & integration

**Envelope format + shared Zod schema** — `designs.editorConfig` is today the clone's page array; a raw Excalidraw scene would be routed to the frozen clone and `calculateDesignPages` (designStore.ts:46-48) would corrupt `pages` to 1 on any PATCH omitting it. Persist `{ format:'excalidraw', formatVersion, scene, assets }` through the existing POST/PATCH `/api/designs` (editorConfig is opaque `unknown` — zero route changes); client always sends explicit `pages` = frame count; teach `calculateDesignPages` to count frames for the new format. Define the envelope + a strict `SkeletonDoc` Zod schema in `@studio/shared` (`designDoc.ts`) — worker-safe, since neither server nor mcp-worker can ever import canvas2 (excal.ts imports CSS; Excalidraw touches `window` at import). Corrections: presets must be mirrored as a **key string union** (`'ig-post'|'story'|…` — `PAGE_SIZE_PRESETS` is an array, not a record); decide string-vs-parsed for `scene` explicitly (`serializeAsJSON` returns a string); sell validation on AI-contract + D1 row size, not editor crashes (Excalidraw's internal `restore(…, {repairBindings:true})` degrades garbage rather than crashing). **M–L, high.**

**Externalize the files map to MM/CDN before persisting (D1 2MB cap)** — `serializeScene` includes `api.getFiles()` base64 dataURLs; one 1.5MB JPEG ≈ 2MB JSON at D1's ~2MB per-value limit — a two-photo post can't be saved at all. Host save pipeline: diff `getFiles()` against the design's `assets` manifest, upload new files via the existing presigned pipeline (`uploadProjectImage.ts` — folder "Diseños", `skipAiAnalysis:true`), persist with `files` omitted; on load rehydrate via fetch→`blobToDataURL`→`api.addFiles` (code shape already in media.ts:41-48, 71-73). Failed uploads keep the save "pending assets" (analogue of the clone's blob-strip + auto-resave, useContentCanvasEditor.ts:308-320). Plan for two verified caveats: `uploadProjectImage` throws when the project has no linked `mediaProjectId` (define the fallback), and rehydration fetches need the MM CDN CORS-readable — be ready to route through the existing `/media/v1` proxy. **L, high.**

**Bypass `sanitizeEditorConfigHtml` for excalidraw envelopes** — both create/update walk every string (design.ts:259-263, 357-360); verified it mutates legitimate Excalidraw text matching the dangerous patterns (pasted `<svg>`/`<script>`, unquoted `onload=` prose via the EVENT_HANDLER regex) — narrower than "any HTML" (`<b>` passes untouched) but enough to break the lossless round-trip and any canonical-JSON baseline compare. Gate: `Array.isArray(editorConfig) ? sanitize(...) : passthrough` (legacy configs are always arrays). Add the server test (`<script>x</script>` in element.text survives for envelopes, stripped for arrays). Also skips a multi-MB recursive walk per save. **S, medium.**

**`useContentCanvas2Editor` + format-routed Lienzo tab** — canvas2 only mounts at /canvas against localStorage; the content page hard-mounts the clone for every design. Branch on the loaded format: legacy array → clone untouched; envelope → `<Canvas2>` keyed on **contentid only** (the documented mid-save designId-flip lesson, page.tsx:821-830); no designId → canvas2 for new designs behind `useExperimentalEnabled()`. Port create-on-first-save (POST design → `updateContent({designId})` → PATCH, with the `isMissingDesignError` recreate ladder) and the captured-contentid `persistContentFields` discipline. Saving serializes **synchronously** from the onReady imperative API (`getSceneElements/getAppState/getFiles`) — the clone's entire stale-debounce machinery is unnecessary. **L, high.**

**Dirty tracking + drafts via the existing UnsavedChangesGuard** — canvas2 has zero navigation/crash safety today. Baseline = canonical JSON of the last saved envelope; compare in the already-debounced `onSceneChange` and publish `hasUnsavedChanges/onSave` into the same `unsavedChangesStore` (guard dialog, save-and-leave, beforeunload for free). Draft `pm:canvas2-draft:<contentid>` = files-stripped envelope, flushed on pagehide/visibilitychange (pattern at useContentCanvasEditor.ts:811-837), restore/discard banner as at page.tsx:800-818. Keep a ~1.5s post-hydration grace window adopting the first onChange as the clean baseline — Canvas2Editor's own init effect (`ensurePagePapers`/`relayoutPages`, Canvas2.tsx:136-169) guarantees a mount echo. **M, high.**

**Fix the /canvas localStorage quota trap (→ IndexedDB)** — CanvasWorkspace.tsx:34-40 stringifies the full scene incl. dataURL files every 400ms and swallows quota errors in an empty catch; one phone photo ≈ ~76% of the origin's ~5MB quota (shared, via the multi-zone, with the whole polimake.com origin), and after the first quota hit **every subsequent edit silently stops persisting**. Split: elements+appState stay in localStorage (KBs); files move to IndexedDB, written once per fileId (immutable), rejoined before `initialScene`; async load instead of the synchronous `useState` JSON.parse; replace the silent catch with a one-shot warning toast. Gate saves on scene identity (see emission hygiene below). This class of bug disappears in the content-page host once assets are externalized. **M, medium-high.**

**Per-page WebP thumbnails through the existing endpoint** — without wiring, canvas2 designs render no card/Kanban/calendar previews. Add `captureThumbnailWebp` (exportToCanvas + `canvas.toBlob('image/webp', 0.85)`, PNG fallback — same Chrome-only wrinkle the clone has); after each save, upload per page to `POST /api/editor/design-thumbnail/upload` (key scheme `design/<pid>/design-preview/<did>/<i>.webp` identical to the clone's), then bump `thumbVersion` only after R2 has the bytes, bound to the captured contentid (discipline at useContentCanvasEditor.ts:441-493). Every existing preview surface then works with zero changes. **M, high.**

**Optimistic concurrency on design PATCH** — `updateDesign` is pure last-write-wins over the whole blob; content is multi-member, and debounced autosave makes two-writer clobbering near-certain. Client sends `baseUpdatedAt`; a ~5-line guard before `updateDesignRecord` (the existing design is already loaded at design.ts:309) returns 409; client offers Recargar vs Sobrescribir via the house ConfirmDialog. Legacy clients omit the field → unchanged. ISO-string equality works. **M, medium.**

**"Usar como imagen de publicación"** — a finished design can't become the published asset without manual download/re-upload, blocking the AI-designs-to-publishing endgame. Host action: export the page at scale 1 → upload via `uploadProjectImage` → `updateContent({ publicationMediaFileId, thumbnailMediaFileId })` (both fields verified correct against publicationResolution.ts). Two verified corrections: **export JPEG, not PNG** — the automation worker sends the original file URL and Instagram's Graph API accepts only JPEG for image containers (`canvas.toBlob('image/jpeg', ~0.9)`; keep PNG for user downloads); and extend `uploadProjectImage` to accept a raw `folderId` (today it only resolves top-level folders by name; the underlying `uploadToMediaLibrary` already takes folderId) to target the content's linked `mmFolder`. Multi-page → sequential uploads feeding the existing IG carousel builder; this is also the seam the MCP worker calls later. **M, high.**

**Coexistence policy: canvas2 never saves over legacy designs** — nothing enforces editor ownership; an unguarded canvas2 PATCH would destroy a clone design (and vice versa). Make the format marker the enforced router + a hard guard: legacy array → mount read-only with "Diseño del editor anterior" + "Duplicar como diseño nuevo (beta)", which creates a *fresh* envelope design seeding one frame per legacy page (size from the R2 preview's intrinsic dimensions or `designs.pages` — the clone is global-page-size anyway) with the already-uploaded R2 preview as full-bleed background via `insertImageFromUrl` + `setAsBackground`. Content keeps its old designId until the user explicitly switches. Known limit: the 8 blob-broken prod designs may seed from blank previews (already data-loss cases). Vector conversion of clone trees is a declared non-goal. **M, medium.**

## Architecture

**`mutate.ts`: version-bumping patchElement + single updateScene funnel** — 25 `as SceneElements` casts across 8 files spread-patch elements without bumping `version/versionNonce/updated`; verified consequence **today**: the store diffs by `id+versionNonce`, so resize/move/rename/lock/opacity/align create *no history entry at all* (silently non-undoable), and any future reconciliation (designs-table merge, autosave race, MCP edit) resolves against stale versions. Add `patchElement` (spread + version+1, fresh versionNonce, updated=now — matching Excalidraw's own `mutateElement` discipline) and `commitElements` as the single updateScene funnel; `duplicatePage` clones additionally strip `index` and reset version. Migrate all call sites and extend `decoupling.test.ts` with a "no `as SceneElements` outside mutate.ts" structural guard. **M, high — prerequisite for the next three entries.**

**One undo step per compound op + non-undoable load migrations** — `resizePage`/`movePage` each issue their own IMMEDIATELY capture then `relayoutPages` issues another (once version-bumping lands, that's two entries with a broken half-state in between); and `ensurePagePapers` on load pushes N history entries for an N-paperless-page legacy scene — the first Ctrl+Z after open deletes a page's paper (page invisible with frame outlines off). Split `relayoutPages` into pure `packPagesInArray` (mirroring zorder.ts's pattern; imageOps.ts already does single-commit correctly), compose resize/move into exactly one IMMEDIATELY updateScene, and batch all load migrations into one updateScene with `CaptureUpdateAction.NEVER` (verified: documented for scene init; doesn't advance the snapshot, so it won't leak into later diffs). Land together with mutate.ts. **M, high.**

**Background color picker: patch in place, preview with EVENTUALLY** — the `<input type="color">` fires per drag tick; each `setPageBackgroundColor` call deletes and rebuilds the paper rect with a fresh id and an IMMEDIATELY capture — dozens of undo entries per pick. Fix: patch the existing paper in place via `patchElement` (a plain spread would be invisible to the store — the versionNonce bump is required); preview ticks use `CaptureUpdateAction.EVENTUALLY` (verified: folded into the next IMMEDIATELY capture; **not** NEVER, which would leave the final change captured nowhere), commit once on blur or a native `change` listener via ref (React exposes no separate change event for color inputs). Test: N calls keep the paper's id stable. **S, medium — depends on mutate.ts.**

**onSceneChange emission hygiene** — verified: `props.onChange` receives `getElementsIncludingDeleted()`, `restoreElements` does not filter `isDeleted`, and nothing prunes files — so tombstones and dead multi-MB dataURLs round-trip and grow forever, and onChange fires on viewport-only ticks so every pan re-runs full host persistence of identical content. Fix in Canvas2.tsx before emitting: filter via the public `getNonDeletedElements` (re-export through excal.ts); prune files to fileIds referenced by surviving image elements (`collectReferencedFileIds`/`pruneFiles` — apply at the **emit/host boundary only**; `serializeScene` already prunes via serializeAsJSON's `filterOutDeletedFiles`, and the in-editor map must stay intact for undo); gate emission on elements-array **identity** (verified reference-stable across viewport-only ticks — O(1) and cheaper than the deprecated `getSceneVersion`; use `hashElementsVersion` if a number is needed) + `viewBackgroundColor` equality. Document the contract in the `onSceneChange` JSDoc: immutable-by-convention snapshot, never mutate, never deep-clone; camera/selection intentionally not persisted. **S, high.**

**Replace the 100ms hydration poll with onChange-driven init** — the settle-poll (Canvas2.tsx:136-169) guesses hydration timing; the races are real but narrow (fresh boot ships the first page inside `initialData`, so no blank-canvas delay — only host-supplied frameless/empty scenes are exposed). Decide from the `initialScene` prop at mount; run migrations in a one-shot imperative `api.onChange` subscription (verified: onChange only fires when `!state.isLoading`, so first fire = hydration committed) and unsubscribe. Note: no hydration component tests exist — they must be written, not relied on. **M, low-medium — cleanup, pairs with the NEVER-migration change.**

**Export error surfacing + multi-page download + PDF naming** — `runExport` swallows every error into console.error (real failure modes: giant canvases — the size prompt accepts 99999px — decode failures, jsPDF memory); "PNG · todas las páginas" fires N anchor clicks that Chrome's download limiter drops silently; the PDF is hardcoded `diseño.pdf`. Add an `onError` prop threaded to the host toast; make PDF the multi-page path (or ZIP — but jszip is a new dependency); name the PDF from the document; per-page try/catch in `exportScenePdf` + release each canvas reference. **M, medium.**

**Component tests + CI smoke; delete dead theme code** — the 30-test suite is pure-logic only; Canvas2.tsx/PageNavigator/LayersPanel (init, gating, menus, export wiring — where most defects above live) have zero tests, and the PARITY Playwright smoke is manual. Add @testing-library/react + jsdom tests against the existing excal mock (fakeApi needs a small onChange extension): single-history-entry ops, signature/stale-label refresh, the init decision matrix; promote the smoke (boot → add page → preset resize → export size) to CI. Delete the unused `Palette.hover`. Dropped from the original: reading Excalidraw's CSS custom properties is **not viable** — they're scoped to the `.excalidraw` element and canvas2's panels are siblings, so `var()` would always hit the fallback; the hand-mirrored hexes stay, documented as an upgrade-checklist item. **M, medium.**

## AI / templates

**Slot model: `customData.c2Slot` on `template:true` designs** — the designs table already has the `template` boolean and `customData` round-trips verbatim (the background.ts precedent), but nothing names "this text is the title, this image is the hero". New `slots.ts`: `c2Slot = { name, kind, role?, maxChars?, brandBinding? }`, with `listSlots` (pure per-page manifest), `markSlot`/`clearSlot`, `applySlotFills` — note: text fills must **rebuild** text elements via `convertToExcalidrawElements` (updateScene does not re-measure), not patch `text` in place. Small "Slot" field on the selected element in the LayersPanel header. This is the foundation the whole AI phase sequences on. **M, high.**

**Skeleton-based generation (`templates.ts` + the shared SkeletonDoc)** — full ExcalidrawElement JSON is hostile to LLM emission (versionNonce, fractional index, boundElements); `ExcalidrawElementSkeleton` lets the AI emit minimal `{type, x, y, text, label, fileId}` (containers auto-create bound text), materialized client-side by `convertToExcalidrawElements(skeleton, {regenerateIds})` — which also measures text correctly, solving the server-can't-measure problem. Server stores AI submissions as `skeleton` in the envelope; the web host converts on first open and re-saves canonical. `applyTemplate(api, skeleton, slotValues)` patches by slot name, converts, offsets into a fresh `addPage` frame. Image slots need bytes via `api.addFiles` — media.ts owns that. **M, high.**

**Server endpoints: template listing + instantiate** — only creator-scoped `listDesignsByCreator` (max 30, no filters) exists. Add `GET /api/projects/:id/designs?template=1` (fields projection, excluding editorConfig) and `POST /api/designs/:id/instantiate` `{projectId, contentId?, slotFills, name?}` — deep-copy the template, store `pendingSlotFills` (text applied client-side on first open; color/image-pointer fills are safe server-side), link `content.designId`. Verified prerequisites the draft missed: `slotsManifest` needs a **new D1 migration + datastore descriptor column** (and prod migrations are out-of-band — single-file `wrangler d1 execute --remote --file`, never `migrations apply`), plus a new index for the projectId listing (only `(createdBy, updatedAt)` exists). **M, high.**

**MCP tools** — tools.ts's 11 tools dead-end at echoing designId. Add `list_design_templates` (project to `{id, name, pages, pageSizes, slots}` — the slot manifest IS the fill contract; never return editorConfig), `create_design_from_template`, `create_design` (free-form skeleton — its zod raw shape generated from the **same** shared SkeletonDoc schema, doubling as model-facing documentation), `attach_design_to_content`. All via StudioClient so the acting-user permission ladder applies. One-line prerequisite: add `@studio/shared` as a `workspace:*` dep of apps/mcp-worker. **M, high.**

**Expose brandKit + bind slots to brand tokens** — projects already store `brandKit` (logos, mainColor, colorPalette, fonts) but the MCP `projectDetail` projection drops it. (a) Add it to the projection — normalize the `headingFont/bodyFont` union (`string | {name,…}`); (b) instantiate resolves `brandBinding` ('mainColor' | 'palette:N' | 'logo:black') server-side — pure pointer substitution; (c) editor `brand.ts`: palette swatches + logo insert via `insertImageFromUrl`, with a documented headingFont→nearest-of-the-current-5-Excalidraw-families mapping (FONT_FAMILY lists 8 but 3 are legacy). **S (a) → M overall, medium.**

**MM images by reference, hydrated client-side** — the worker can't run media.ts (FileReader/Image/fetch) and inlining a photo breaches D1's 2MB value limit. AI/template image slots carry `customData.c2Media = { mediaFileId, projectId }` and no fileId; a canvas2 `hydrateMediaRefs(api, resolver)` (host-injected resolver → the existing projectMedia proxy) inlines via `insertImageDataURL`/`addFiles` on first open, placeholder until hydrated; saves strip `files` entries whose element carries `c2Media` (re-hydratable). Pre-build verification task: confirm image.polimake.com sends CORS for the app origin, else route hydration through the server media proxy. Complements (does not duplicate) the user-image externalization in Persistence. **M, high.**

**Design lint guardrails** — Zod guarantees well-formed JSON, not a usable design (title under Story chrome, 8px text, white-on-white against the `#ffffff` paper). `designLint.ts` in `@studio/shared` (pure, worker-safe): per-preset safe-area boxes (as tunable data constants shared with the editor's safe-area overlay), min effective fontSize (resizePage's floor of 4 is a rendering floor, not legibility), contrast vs page background, out-of-frame bounds, required-slot coverage + maxChars. Run in instantiate/create, return structured `{warnings:[{code, slot?, pageId, message}]}` through the MCP tools — warnings, not failures, so the model self-corrects. Sequenced last (needs the slot manifest + shared presets). **M, medium.**

## Performance

**Self-host Excalidraw fonts** — `EXCALIDRAW_ASSET_PATH` is set nowhere and 0.18's bundle falls back to `https://esm.sh/...` for its woff2 fonts (verified in dist/prod/chunk-K2UTITRG.js); neither the app CSP (`font-src 'self' data: fonts.gstatic.com`) nor the **enforcing** polimake.com multi-zone CSP allows esm.sh — wrong fonts in exactly the production deployment, plus a third-party availability dependency. Copy `dist/prod/fonts` → `apps/web/public/excalidraw/fonts` via a prebuild step and set `window.EXCALIDRAW_ASSET_PATH = withBasePath('/excalidraw/')` at CanvasWorkspace module scope (works despite import hoisting — font URLs are constructed lazily at Fonts init). Verify: zero esm.sh requests from /canvas. **S, high.**

**PDF export: JPEG frames + lazy jspdf** — per-page full-res `toDataURL('image/png')` into jsPDF (which re-deflates PNG) peaks at hundreds of MB on a 10-page photo deck, and the static `import { jsPDF }` ships 343KB min in the canvas2 chunk on every mount though PDF export is rare. Pass the HTMLCanvasElement directly to `doc.addImage(canvas, 'JPEG', …)` (DCTDecode passthrough, no re-encode; opacity is guaranteed — white paper + `exportBackground:true` default; keep PNG as an opt-in flag), and `await import('jspdf')` inside `exportScenePdf` so Next splits it. **S, medium.**

**Panel onChange gating** — both panels rebuild O(n) signature strings on every onChange tick (incl. every pan/zoom), and the LayersPanel signature provably misses text content — labels go stale after text edits. Corrected fix: the cheap gate is the **elements array reference** (verified cached and stable across viewport-only ticks) + the `selectedElementIds` object reference — `getSceneVersion` is deprecated and itself O(n); use `hashElementsVersion` (via excal.ts) where a number is needed. **Depends on mutate.ts** — hash-gating with today's non-bumping patches would make the panels stale after rename/lock/align. Skip the rAF-coalescing half (onChange already fires at most once per React commit). Longer term, `useSyncExternalStore` instead of the setTick hack. **S, medium.**

(IndexedDB persistence and emission gating — filed under Persistence and Architecture respectively — are the other two perf-critical items.)

## Phase sequencing

**Phase 0 — correctness hygiene (small, independent, do first):**
Self-host fonts · `mutate.ts` version bumps → then single-updateScene compound ops + NEVER load migrations + color-picker fix + panel gating (all depend on it) · onSceneChange emission hygiene (tombstones/files/identity gate) · sanitizer bypass · window.prompt replacements · text-preset fixes. Rationale: undo is silently broken and persistence would fossilize today's bloated, tombstone-laden scenes — fix the substrate before storing anything.

**Phase 1 — daily-driver UX (parallel with late Phase 0):**
Viewport-following active page · viewMode chrome gating · insert-after-active · strip scalability · first-run format chooser + 1080×1350 default · safe-area overlays. These make /canvas trustworthy before it meets real content. Thumbnails/grid (L) can start here and land whenever.

**Phase 2 — persistence to the designs table (the planned next phase; strictly ordered):**
Envelope + shared Zod schema first (everything keys on the marker) → file externalization (removes the D1 2MB blocker) → host hook + format-routed mount + coexistence guard → dirty tracking/drafts → WebP thumbnails → optimistic concurrency → IndexedDB for the /canvas playground. The envelope and schema live in `@studio/shared` from day one because Phase 4 validates against them.

**Phase 3 — publish + capabilities:**
"Usar como imagen de publicación" (JPEG; needs Phase 2's save flow) · shape library · clipboard/paste · renderTopRightUI save status (needs Phase 2's save state) · presentation mode (needs viewMode gating) · MainMenu curation · embeddable video (L, independent).
